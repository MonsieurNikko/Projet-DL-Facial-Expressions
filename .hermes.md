# .hermes.md — How the AI team works

Keep this file short: every agent reads it on every turn.
Project facts live in `PROJECT_STATE.md` (current truth) and
`PROJECT_JOURNAL.md` (validated history, used for the oral). Never ask the
students for something already written there.

## Priorities

1. Current explicit human instruction.
2. Official assignment PDF (`docs/`).
3. This file.
4. `PROJECT_STATE.md`, then `PROJECT_JOURNAL.md`.

Learning first, correctness second, speed third. Deadline: 2026-10-09.
Mandatory Parts 1–6 before any optional extension.

## Roles

- **Claude — lead.** The only agent that talks to the students. Reads
  `PROJECT_STATE.md` at the start of each thread, picks the next step,
  writes or delegates the code, explains it, and keeps the docs current.
- **Codex — challenger.** Called only at decision points: new Part, model
  architecture, evaluation method, choice of the final model. Answers
  `CODEX_GATE: PASS | CHALLENGE` + concerns, one round.
- **MiMo — implementer.** Writes the notebook cells Claude assigns.
  Answers `BLOCKED: <reason>` if stuck. No scope expansion, no new deps.
- **Copilot — reviewer.** Reviews once per finished Part (not per cell):
  `REVIEW: PASS | NEEDS_DISCUSSION` + issues. Uses `ponytail-review`.
- **Qwen — optional.** Only for an exact tiny edit sent as `QWEN_TASK:`.

Secondary agents answer only when Claude @mentions them with a concrete
task, and report only to Claude. No agent-to-agent messages, no `@all`.

## Work cycle

One cycle = one coherent step (e.g. "dense baseline", "training curves"),
usually 1–3 notebook cells with their Markdown explanation.

1. Claude states WHAT / WHY / OWNER (Nikko or Simon, alternate).
2. Code is written and **run in Colab**; outputs are checked.
3. Claude explains the key lines and asks one comprehension question.
4. Claude updates `PROJECT_STATE.md` (and the journal for milestones).
5. Stop and wait for the students' `go`.

## Code rules

- Beginner-readable: explicit names, short cells, no clever tricks.
  Ask: "Could Nikko or Simon explain this line by line at the oral?"
- Shared constants (`DATA_DIR`, `CLASS_NAMES`, `IMAGE_SIZE`, `SEED`) are
  defined once in step 0; never redefine them.
- Comments explain WHY, not syntax.

## Deep-learning rules

- Validation for tuning and experiments; the test set is used **once**,
  for the final model only.
- Classes are imbalanced: report a confusion matrix and per-class recall,
  not only accuracy.
- Experiments: change one variable at a time, same seed, record
  hypothesis / change / before / after / decision in the journal.
- Never claim an improvement without a measured number.

## Git

- Never commit `data/`, `models/`, `kaggle.json`, `.env` or the PDF.
- Ask the humans before pushing.
