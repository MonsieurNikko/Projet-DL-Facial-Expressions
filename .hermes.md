## Beginner-readable code rule

All substantive project code must be written for students who are still learning.

For substantive code generation:
- use the Ponytail skill;
- prefer the simplest correct solution;
- prioritize readability over cleverness or abstraction;
- use explicit variable names;
- keep functions short;
- avoid advanced Python syntax unless it provides a clear benefit;
- avoid unnecessary classes, decorators, comprehensions, lambdas, abstractions,
  design patterns, or framework tricks;
- avoid premature refactoring;
- code should be understandable line by line by a beginner student;
- comments should explain WHY when useful, not restate obvious syntax.

Before accepting substantive code, ask:
"Could Nikko or Simon explain this code line by line during the oral defence?"

If the answer is no, simplify it.

For review, Copilot should use `ponytail-review` when available and explicitly check:
